# Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a MkDocs Material documentation site for ConsentML — 13 pages, a generated API reference, CI that builds it strictly and refuses to publish petition framing, and the repo hygiene files a public project needs.

**Architecture:** Sources live in a new `docs-site/` tree (never `docs/`, which holds private internal specs). `mkdocs.yml` sits at the repo root. Narrative pages are hand-written; the API reference is generated from existing docstrings by mkdocstrings so it cannot drift. A shell gate greps published sources for petition terminology and fails the build on any hit. Deployment is written now but gated on the repo being public, so it activates at launch without a workflow edit.

**Tech Stack:** MkDocs, mkdocs-material, mkdocstrings[python], GitHub Actions, bash.

**Spec:** `docs/superpowers/specs/2026-08-14-docs-site-design.md`

## A note on prose tasks

Tasks 3–7 create documentation pages. For each page this plan gives the exact
path, its nav entry, the sections it must contain, every code block verbatim,
the facts it must state, and what it must not say. **The prose itself is the
implementer's to write** within those constraints — this plan does not
ghost-write it.

Two rules bind every page:

- **Never invent behavior.** Every claim must be checkable against `src/` or
  the README. If a page needs a fact you cannot verify in the code, stop and
  ask rather than writing something plausible.
- **Match the existing voice.** Plain and direct. Read `README.md` and the
  module docstrings in `src/consentml/verify.py` first. No marketing register,
  no hype, no exclamation marks.

## Global Constraints

- Python floor **3.10** (`requires-python = ">=3.10"`).
- Runtime `dependencies` stay exactly `["pandas>=2.0"]`. Docs tooling goes in a new `docs` optional extra only.
- Sources live in **`docs-site/`**, never `docs/`. `docs/superpowers/` holds private internal specs and plans and must never be published.
- Every build runs `mkdocs build --strict`.
- **No petition framing in anything that ships.** The terms `EB1`, `petition`, `USCIS`, `adjudicator`, `immigration`, `criterion` must not appear (case-insensitively) in `docs-site/`, `mkdocs.yml`, `README.md`, or `CONTRIBUTING.md`. The Why pages are rewritten from the design spec, never pasted.
- No versioned docs (`mike`), no blog plugin, no custom theme, no `mkdocs-jupyter`.
- The existing test suite must stay green at 100% coverage. Nothing in this plan touches `src/`.
- Match existing house style in prose: plain, direct, no hyperbole.

- [ ] **Step 1: Write the failing tests**

Create `tests/test_docs_gate.py`:

```python
"""The published-docs term gate.

The Why pages are rewritten from a design document written for a different
audience. Prose review catches that once; a grep catches it every time,
including on edits nobody is watching.
"""

import subprocess
from pathlib import Path

import pytest

SCRIPT = Path(__file__).resolve().parents[1] / "scripts" / "check-docs-terms.sh"


def _run(*paths):
    return subprocess.run(
        [str(SCRIPT), *[str(p) for p in paths]],
        capture_output=True,
        text=True,
    )


def test_clean_tree_passes(tmp_path):
    (tmp_path / "page.md").write_text("# ConsentML\n\nA lineage tool.\n")
    result = _run(tmp_path)
    assert result.returncode == 0, result.stdout + result.stderr


@pytest.mark.parametrize(
    "term",
    ["EB1", "petition", "USCIS", "adjudicator", "immigration", "criterion"],
)
def test_each_forbidden_term_fails(tmp_path, term):
    (tmp_path / "page.md").write_text(f"# Why\n\nThis supports the {term}.\n")
    result = _run(tmp_path)
    assert result.returncode == 1
    assert term.lower() in (result.stdout + result.stderr).lower()


def test_matching_is_case_insensitive(tmp_path):
    """A lowercase heading anchor or URL slug must not slip past."""
    (tmp_path / "page.md").write_text("# Why\n\nsee /eb1-notes for detail.\n")
    assert _run(tmp_path).returncode == 1


def test_nothing_to_scan_is_a_failure(tmp_path):
    """A gate that silently passes because the paths moved is not a gate."""
    assert _run(tmp_path / "does-not-exist").returncode == 1
```

- [ ] **Step 3: Write the script**

Create `scripts/check-docs-terms.sh`:

```bash
#!/usr/bin/env bash
# Fail if petition framing reaches anything published.
#
# The Why pages are rewritten from a design document written for a different
# audience. This gate is mechanical on purpose: prose review protects the
# first draft, a grep protects every later edit.
#
# Usage: check-docs-terms.sh [PATH...]
#   With no arguments, scans the published set. Paths that do not exist are
#   skipped, so this works before CONTRIBUTING.md is added.
set -uo pipefail

TERMS='EB1|petition|USCIS|adjudicator|immigration|criterion'

if [ "$#" -gt 0 ]; then
    CANDIDATES=("$@")
else
    CANDIDATES=(docs-site mkdocs.yml README.md CONTRIBUTING.md)
fi

TARGETS=()
for path in "${CANDIDATES[@]}"; do
    [ -e "$path" ] && TARGETS+=("$path")
done

if [ "${#TARGETS[@]}" -eq 0 ]; then
    # Never pass by default. If the paths moved, the gate is broken, and a
    # broken gate that exits 0 is worse than no gate.
    echo "check-docs-terms: nothing to scan; the paths moved or are wrong" >&2
    exit 1
fi

if grep -rniE "$TERMS" "${TARGETS[@]}"; then
    echo "" >&2
    echo "check-docs-terms: the terms above must not appear in published" >&2
    echo "documentation. Rewrite the wording rather than deleting the page." >&2
    exit 1
fi

echo "check-docs-terms: clean (${TARGETS[*]})"
```

Then make it executable:

```bash
chmod +x scripts/check-docs-terms.sh
```

- [ ] **Step 2: Write `migrating.md`**

1. `## When you need it` — v0 and v1 databases are readable but not writable.
2. `## Running it` — `consentml migrate --db lineage.db`.
3. `## What it does` — builds alongside and renames atomically, keeps `<name>.pre-migration.bak`, refuses if the pre-migration verification fails.

- [ ] **Step 3: Write `anchoring.md`**

Source: `README.md` "Anchoring" (lines 149–165) and `verify_audit_log`'s docstring. Required sections:

1. `## The limit of a hash chain` — a chain cannot detect an attacker who rewrites the whole log from genesis and recomputes every hash.
2. `## Recording an anchor` — take the `head_hash` from `verify` and store it outside the database.
3. `## Checking it` — `consentml verify --db lineage.db --expected-head <hash>`.
4. `## Why membership, not equality` — the anchor is looked up across the whole chain, so a log that legitimately grew still verifies; only a rewrite or truncation reports `head_mismatch`. Equality would fire on every run once the log grew, training operators to ignore it.
5. `## What it does not prove` — nothing about entries appended after the anchor. Re-anchor regularly to narrow that window.

## Task 6: Why ConsentML

**Files:**
- Create (replacing placeholders): `docs-site/why/index.md`, `docs-site/why/threat-model.md`

**This is the task the leak gate exists for.** Source material comes from a
design document written for a different audience. Rewrite from it; never paste.

- [ ] **Step 1: Write `why/index.md`**

Required sections:

1. `## The problem` — most organisations running production ML cannot answer two questions: which deployed models were trained on a given user's data, and what evidence they can produce that those models were addressed. The reasons are structural, not naivety: pipelines do not preserve the link between a deployed artifact and the records that produced it, and reproducing training data after the fact is unreliable because source tables drift.
2. `## Reporting, not deletion` — ConsentML identifies which models a subject's data reached and records what the operator decided. It does not modify databases, models, or deployment infrastructure. Give the three reasons: legal responsibility sits with the operator; "delete from a model" is an open research problem (for scikit-learn it means a full retrain, for fine-tuned LLMs there is no good answer); and a tool that promised deletion would be overpromising.
3. `## How it differs from adjacent tools` — a compact table, one row each:

| | What it does | How ConsentML differs |
|---|---|---|
| Compliance platforms (OneTrust, BigID, Securiti) | Configuration-driven privacy suites | Integrates at the training function, in code, not at the data lake via a dashboard |
| Lineage frameworks (OpenLineage, DataHub, Marquez) | Generic pipeline lineage | Per-subject lookup and revocation events are first-class, not built on top |
| Machine unlearning research | Modifies model weights to remove an example's influence | Operates upstream, on the lineage; identifies what would need unlearning |
| Experiment trackers (MLflow, W&B) | Reproducibility and comparison | Records lineage specifically to answer "which models learned from this person?" |

4. `## Standards` — a short table mapping to NIST AI RMF (GOVERN-1.4 documentation, MAP-2.3 system operation, MANAGE-2.3 response plans), GDPR Article 30 records of processing and Article 17 erasure, and CCPA/CPRA audit-trail expectations. Keep it to the table plus two sentences.

Do not include a section arguing originality. The table is the whole treatment.

- [ ] **Step 2: Write `why/threat-model.md`**

Source: design spec §8. Required sections:

1. `## What ConsentML protects against` — lineage loss between training and deployment; inability to answer a regulator's query; post-hoc tampering with the audit log.
2. `## What it does not protect against` — someone removing the decorator from their training code; someone editing the SQLite file directly (the chain detects this only when verification is actually run); inference-time leakage such as membership inference, for which this is not a substitute for differential privacy; an adversarial operator.
3. `## Trust assumptions` — the trust model is appropriate for a compliance support tool, not a security tool. The user is the principal. ConsentML helps an operator demonstrate compliance; it does not enforce compliance against an operator who does not want to comply.

```yaml
name: Docs

on:
  push:
    branches: [main]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # First, before anything is built: a leaked term must never reach an
      # artifact, even one that is thrown away.
      - name: Check for forbidden terms in published docs
        run: ./scripts/check-docs-terms.sh

      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
          cache: pip

      - name: Install
        run: pip install -e ".[docs]"

      - name: Build
        run: mkdocs build --strict

      - name: Upload the built site
        uses: actions/upload-artifact@v4
        with:
          name: site
          path: site/

  deploy:
    needs: build
    runs-on: ubuntu-latest
    # Only from main, and only once the repository is public. While it is
    # private this is a no-op; the first push after it goes public deploys,
    # with no workflow edit needed at launch.
    if: >-
      github.event_name == 'push' &&
      github.ref == 'refs/heads/main' &&
      github.event.repository.private == false
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
          cache: pip

      - name: Install
        run: pip install -e ".[docs]"

      - name: Deploy to GitHub Pages
        run: mkdocs gh-deploy --force
```
